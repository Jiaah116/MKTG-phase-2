# TeamFit Data and Decision Table

| Data or decision | Source | Purpose | Access rights | Sensitivity | Storage and retention | Permitted action | Required approval | Human owner |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Client request text | Manager pastes text into the local Request Review workspace | Review the original request; optionally create an interpretation draft | Local user in the browser; when interpretation is selected, the TeamFit server sends this text to OpenAI | May contain client information; real-client sensitivity classification is **Not verified** | Held in page memory during the browser session. Browser storage is not used. Server request text is not logged. TeamFit sets `store: false` on the OpenAI request. OpenAI-side retention and access policies were not verified for this prototype. | Manager may review, edit, or submit the text for optional interpretation | Manager chooses **Interpret message** before any request text is sent to OpenAI | Manager reviewing the request |
| Optional AI interpretation request | TeamFit server builds the request from pasted client text plus fixed extraction instructions and a fixed schema | Extract stated deliverables, quantities, deadlines, materials, missing information, and clarification questions | Server uses the local API key; OpenAI receives only the request text, instructions, and schema | Same sensitivity as client request text | Server does not persist the request text in logs. TeamFit sets `store: false` on the OpenAI request. OpenAI-side retention and access policies were not verified for this prototype. | Create an editable extraction draft with evidence excerpts; no automatic staffing or assignment | Manager must review the draft and explicitly approve selected supported facts before copying them to manual fields | Manager reviewing the draft |
| Confirmed request details | Manager-entered title, work description, skill, effort estimate and confirmation, dates, and materials | Determine blockers and enable the rule-based capacity check only when required inputs are complete | Local user in the browser | Request details may be client-sensitive; classification is **Not verified** | Held in page memory for the current browser session; no saved request history | Edit details, assess completeness, run capacity check after required confirmation | Manager enters and confirms the effort estimate; manager reviews committed work when dates change | Manager reviewing the request |
| Synthetic team and workload data | Built-in synthetic members; manager may edit the local table | Demonstrate skills, daily capacity, committed work, and availability freshness for aggregate planning | Local user in the browser only | Explicitly synthetic in the prototype | Held in page memory during the current browser session; no persistence | Edit synthetic data; use it in the local capacity calculation | Manager reviews committed work for selected dates before confirmed capacity is used | Manager reviewing capacity |
| Capacity results | Local rule-based calculation: daily capacity × inclusive weekdays − committed work | Identify potential candidates, lack of capacity, skill mismatch, or missing availability/commitment information | Local user in the browser only; not sent to OpenAI | Derived planning information; real-world sensitivity is **Not verified** | Held in page memory until relevant inputs change or the page refreshes | Show aggregate planning results and calculation breakdowns; never assign work automatically | Manager must review schedule and dependencies before recording a candidate-selection decision | Manager reviewing capacity |
| Session-only hold decision | Manager selects hold and enters a non-empty decision note | Record that capacity may be unassessed and request follow-up is needed | Local user in the browser only | Decision note may contain client or operational information; classification is **Not verified** | Held only in the current browser session; the UI states it is not saved after refresh | Record a hold message for the open review; no client message or assignment is sent | Manager must explicitly select the hold option and provide a non-empty decision note | Manager recording the hold |
| Session-only candidate-selection decision | Manager selects a potential candidate after a current capacity check | Record a manager follow-up decision without assigning work | Local user in the browser only | Decision note and candidate selection may be operationally sensitive; classification is **Not verified** | Held only in the current browser session; the UI states it is not saved after refresh | Record a candidate-selection decision for manager follow-up; no assignment or client commitment is created | Current capacity check, selected potential candidate, non-empty note, and manager schedule/dependency confirmation | Manager recording the decision |
